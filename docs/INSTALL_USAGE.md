# 纯净代理 1.1.1：安装和使用说明

适用于 Android 7.0 及以上。应用免费、无广告，节点需要自行导入。源码与下载入口：[pure-proxy-android](https://github.com/kongwen686/pure-proxy-android)。

## 1. 选择安装包

从 [GitHub Releases](https://github.com/kongwen686/pure-proxy-android/releases/latest) 下载正式签名包。展开页面底部的 **Assets**：

| 文件 | 适用设备 |
| --- | --- |
| `pure-proxy-1.1.1-arm64-v8a.apk` | 大多数现代 Android 手机，体积更小 |
| `pure-proxy-1.1.1-universal.apk` | 包含 arm64-v8a、armeabi-v7a、x86、x86_64；不确定架构时选这个 |
| `SHA256SUMS.txt` | 下载文件的 SHA-256 校验值 |
| `INSTALL_USAGE-zh-CN.md` | 本说明的独立下载文件 |
| `APK_VERIFICATION.json` | 签名、架构、版本、校验值等发布检查结果 |

两种 APK 的功能相同，安装任意一种即可；通用包不会增加代理功能。GitHub 自动生成的 `Source code` 压缩包是源码，不能直接安装。Actions 中的 Debug APK 使用测试签名，不能覆盖本项目的正式签名安装包。

## 2. 安装和覆盖升级

1. 用手机浏览器下载 APK，或将下载的 APK 传到手机。
2. 在下载列表或文件管理器中打开 APK。如果系统提示，给当前浏览器或文件管理器开启“允许安装未知应用”，然后完成安装。
3. 已装本项目 1.0.0 / 1.1.0 的用户，先断开代理，直接覆盖安装 1.1.1。沿用同一发布签名，并提高安装版本号；无需先卸载。
4. 打开“纯净代理”，检查已有节点与链式设置，再重新连接。

首次安装时没有预置节点。卸载会删除本机节点和设置；需要卸载前，请自行保存配置。若提示签名不一致，请检查是否安装了自行构建或 Actions 的 Debug 包。若提示设备不兼容，尝试通用包，并确认系统版本符合要求。

## 3. 扫码、图片或链接导入

1. 打开首页，点击右上角“＋”，选择扫描二维码；首次扫描时允许相机权限。
2. 二维码在另一台设备上时，直接对准扫描；二维码保存在本机时，通过扫码页面的图片入口导入。
3. 也可以复制完整节点链接，再从“＋”菜单选择从剪贴板导入；没有二维码或链接时，选择对应协议手动填写。
4. 核对节点协议、地址、端口及服务商提供的认证信息。订阅链接导入后需成功获取内容；未出现节点时，使用“更新订阅”重试，并检查链接是否有效。

支持 Shadowsocks、VLESS/REALITY 等上游协议。二维码只自动填入其包含的信息，不会自动提供服务器、续费节点或取得缺失的密码。

## 4. 普通单节点连接

1. 点选要使用的节点，点击右下角连接按钮。
2. 首次连接时同意 Android 系统的 VPN 授权。状态栏会出现 VPN 标识。
3. 使用已纳入代理的浏览器打开网页，并检查实际公网出口。
4. 再次点击连接按钮可断开。修改节点、链式、路由或分应用设置后，先断开再重连。

VPN 标识表示 VPN 服务已启动，不能单独证明远程节点连通或全部流量使用同一出口。

## 5. 中转 → 静态出口的链式代理

1. 分别导入中转节点和出口节点，建议放在不同分组。
2. 静态出口为 SOCKS5 时，填写服务商提供的地址、端口，以及账号密码或白名单认证信息。
3. 首页打开左侧菜单 → “链式代理”。选择中转所在分组及中转节点。
4. 切换到“静态出口（链式代理）”，选择出口节点；“可选前置代理”默认保持“不使用”。
5. 核对路径：**手机 → 中转 → 静态出口 → 网站**，点击“保存并选中中转节点”。
6. 返回首页断开并重新连接，再用走代理的浏览器检测公网 IP。网站看到的应是出口服务实际提供的公网 IP；不一定与 SOCKS 接入地址相同。

恢复单节点：链式页面选择“普通代理（单节点）”，保存后断开重连。需要三跳时，链路为“手机 → 前置 → 中转 → 出口 → 网站”。节点删除或订阅更新更换节点标识后，需要重新选择节点；出口失败时不会自动改用中转作为代理出口。

链式设置作用于所选分组，只改变被路由到代理的流量。IP 是否静态、独享，以及其国家、类型和质量，由出口服务提供者决定。更多范围及错误处理见 [CHAIN_PROXY.md](../CHAIN_PROXY.md)。

## 6. 分应用、绕行、勾选分别是什么意思

“直连”指使用手机原有 Wi-Fi 或移动网络直接访问网站；“代理”指通过所选节点访问，链式模式下再经配置的出口。

分应用设置决定哪些应用的流量进入本应用的 VPN：

| 启用分应用 | 绕行模式 | 勾选的应用 | 未勾选的应用 |
| --- | --- | --- | --- |
| 关闭 | 任意 | 不按勾选列表筛选，通常进入 VPN | 不按勾选列表筛选，通常进入 VPN |
| 开启 | 关闭 | 进入 VPN，按路由规则处理 | 绕过本应用的 VPN |
| 开启 | 开启 | 绕过本应用的 VPN | 进入 VPN，按路由规则处理 |

**进入 VPN 不等于所有请求必走代理。** VPN 内部的路由规则仍可能选择直连；要让目标应用通过节点连接，应同时检查路由设置。VPN 排除本应用自身的连接，以避免循环。

例如仅让浏览器和某个海外应用进入 VPN：开启“启用分应用”，关闭“绕行模式”，勾选这些应用，保存后重连。若应用在 GBox 等容器中运行，还需检查容器应用是否被纳入 VPN。

当前实现中，分应用已开启但列表为空时，会按不筛选应用处理，不能用空列表表示“没有应用进入 VPN”。

## 7. 常见问题

- **浏览器正常，某个应用无法联网：**检查它是否被分应用规则排除，是否在容器内运行，以及路由、节点是否有效；修改后重连。
- **链式连接失败：**检查出口认证、端口、服务商白名单和节点选择。仅导入两个节点，并不代表已经启用链式模式。
- **浏览器出口正确，但应用商店地区未改变：**代理改变网络出口，不会自动修改 Google Play 账号的国家/地区、支付资料或第三方服务账号区域。
- **无法覆盖安装：**确认下载的是正式 Release 包；签名、设备架构和系统版本须兼容。不要为了尝试升级而先卸载已有配置。

发布前会检查签名、APK 对齐、版本、架构及敏感信息，并运行自动测试；本次没有通过连接 Android 真机完成安装、扫码、VPN 生命周期和实际出口的逐项验收。应用没有附带可用节点、个人代理密码、订阅令牌或签名私钥。
